# NETRIVA POKER PRO — контекст за работа

Кратък наръчник за всяка следваща сесия. Прочети това **преди** да пипаш кода.

---

## 1. Къде живее платформата

| Какво | Къде |
|---|---|
| Жив сайт | https://netriva-poker.onrender.com |
| Хранилище | https://github.com/krastev111-bot/netriva-poker |
| Хостинг | Render (безплатен план, авто-деплой от `main`) |

Структура в хранилището:

```
netriva-poker/
├── server.js        ← Node.js + Socket.IO (главната папка)
├── VERSIONS.md      ← дневник на версиите (главната папка)
└── public/
    └── index.html   ← целият клиент: HTML + CSS + JS в един файл
```

## 2. Как се качва нова версия

**Важно: от облачната среда на Claude няма достъп до GitHub и Render — блокирани са.**
Затова редът е: Claude прави файловете → изпраща ги → Иван ги влачи в GitHub.

1. `index.html` → https://github.com/krastev111-bot/netriva-poker/upload/main/public
2. `server.js` и `VERSIONS.md` → https://github.com/krastev111-bot/netriva-poker/upload/main
3. Commit message = номерът на версията (`v49`)
4. Render хваща commit-а сам · **3–5 минути** (безплатният план е бавен)
5. В браузъра: **Ctrl+F5**; баджът горе вдясно трябва да покаже новия номер

Ако баджът остане стар: или деплоят още не е минал, или `index.html` е отишъл в главната папка вместо в `public/`.

## 3. Версията се сменя на две места

При всяка промяна в `index.html`:

```js
const NV_VER="v49 · 26.07";                        // ~ред 1450, показва се в баджа
```
```html
<span class="ver" id="verTag">v49</span>           <!-- ~ред 693, начална стойност -->
```

## 4. Как се тества преди качване

Средата на Claude може да пусне цялата платформа локално и да я изиграе наистина:

```bash
cd netriva && npm install express socket.io
setsid nohup node server.js > /tmp/srv.log 2>&1 < /dev/null &   # порт 3000
```

Chromium е предварително инсталиран на `/opt/pw-browsers/chromium`; Playwright го намира сам
(`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`). **Не пускай `playwright install`.**

Задължителни проверки преди доставка:

- `node --check` върху извлечения inline скрипт (изрежи `<script>…</script>` с regex)
- Броене на `{` и `}` в `<style>` — трябва да съвпадат
- Автоматичен обход на **13 размера екран** (360 → 2560px): нула хоризонтално преливане,
  нула места извън екрана, нула застъпвания с дясната колона, нула JS грешки
- Реална игра: създай маса, изиграй 10–20 ръце, направи екранни снимки

Полезен трик: `page.on('pageerror')` улавя JS грешки, които иначе минават незабелязано.

## 5. Как е устроен кодът

### `server.js` — единственият, който вижда тестето
- Стаи в паметта (`rooms` Map), код от 5 знака, 8 места, ботове допълват
- **Provably fair:** сървърът публикува SHA-256 печат на тайния seed **преди** раздаването;
  след ръката разкрива seed-а. `HMAC-SHA256(serverSeed, clientSeeds + ":" + nonce)` дава разбъркването.
- Пълната история на всяка ръка (включително **цялото тесте** и докъде е стигнало раздаването)
  се праща на клиента със събитие `history` — от там идват „сенчестите" карти в клиента
- Ботове с рационал: всяко решение носи текстово обяснение (`pendingReason`), което влиза в историята
- Странични потове, all-in рънаут с обръщане на картите, equity в реално време
- Таймери: 45 сек. за ход на човек (после авто-check/fold), 90 сек. гратис при разпадане на връзката

### `index.html` — всичко в един файл
Няма build, няма зависимости освен `/socket.io/socket.io.js`. Редът е:
`<style>` → разметка → един голям IIFE със `"use strict"`.

Ключови глобални: `S` (състояние от сървъра), `mySeat`, `myHole`, `HIST` (историята),
`stackHist` (стекът по ръце), `steps` (трите пре-флоп размера, пазят се на устройството).

Ключови функции: `render()` → `renderTable()` + `renderControls()`; `drawGraph()` / `axisSVG()`;
`renderHist()`; `syncHist()`; `ghostBoard()`; `buildPreRow()`.

## 6. Правила, които държат нещата да не се чупят

1. **Промяна в клиента ≠ промяна в сървъра.** Повечето сесии пипат само `index.html`.
   Кажи изрично кои файлове се качват, за да не се качва излишно `server.js`.
2. **Специфичност на CSS.** `.dock` идва след `.actdock` в стила, затова е нужно `.dock.actdock`.
   Внимавай при добавяне на правила преди дефиницията на основния клас.
3. **Никакви емоджита в интерфейса.** Рендират се различно (или изобщо не се рендират)
   на различни системи. Всяка иконка е inline SVG — щит, мегафон, карти, молив.
4. **Мобилният изглед има отделни правила** в `@media(max-width:760px)` и `@media(max-width:390px)`.
   Всяка нова контрола изисква ред и там.
5. **Местата на играчите могат да излязат извън масата** и да се застъпят с дясната колона.
   Решено с `@media(min-width:901px){ .table{left:46px;right:46px} }` — не пипай без причина.
6. **Числата са в бяло и удебелени**, цвят носи само стрелката ▲/▼ или контекстът.
   Това важи за блайндовете, стека, разликата, номерата на ръцете.

## 7. Какво е правено досега (накратко)

- **v43–v46** — мобилен изглед, авто-действия, клавишни комбинации, muck/show, бележки за играчите,
  графика на стека, сгъваем панел „Честна игра", брояч в бутона „Нова ръка"
- **v47** — стекът в дясната колона, пулсиращ щит, авто-действията вече не мигат, док за двата бутона
- **v48** — махнати реакциите; постоянен SHA-256 печат (бяло на черно) с местене навън/навътре;
  графика с координатна система и растящ мащаб; почукване по плъзгача = 1 BB; ръчно въвеждане
  в пре-флоп реда; Fold/Call в док; по-широка дясна колона; векторно мегафонче
- **v49** — пост-флоп редът подравнен на 560px; историята свършва наравно с блока за действия
  (~12 ръце при твой ред); хайлайт на колелцето и „Нова ръка"; фолднатите карти се виждат и след
  края на ръката; „сенчести" карти на борда за неразиграните улици, обръщат се при посочване

Пълните описания са във `VERSIONS.md`.

## 8. Отворени идеи

- Многоезичност (BG/EN) — превключвател в лобито и настройките; речник и в двата файла
- Потвърждение при All-in (срещу неволно щракване)
- В `server.js` стои неизползван обработчик `react` — остатък от махнатите емоджи реакции.
  Може да се изчисти при следващо качване на сървъра.
